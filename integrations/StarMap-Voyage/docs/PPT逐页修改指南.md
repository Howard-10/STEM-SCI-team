# ResearchPilot PPT 逐页修改指南

> 使用说明：每页按"现状 → 问题 → 怎么改 → 具体文案"四步组织。你可以按页码逐页对照修改。

---

## 第 1 页 · 封面

**现状：** 标题 + 副标题 + 汇报人/日期，结构完整。

**问题：** 副标题"让科研工作者的每一分努力都有回响"偏虚，观众不知道这个项目具体做什么。

**怎么改：** 只改副标题文案。

**修改后文案：**

```
主标题（保持）：AI 赋能科研全流程 ResearchPilot | 科研增效工作台
副标题（替换）：从文献综述到论文写作的 AI 协作闭环
底部（保持）：汇报人：XXX ｜ 2026年6月
```

> 把原副标题 Slogan 移到第 14 页结尾用。

---

## 第 2 页 · 背景与痛点引入

**现状：** "01 / 背景与痛点"，三段长文字。

**问题：** 满屏段落文字，听众 5 秒内抓不到核心信息。

**怎么改：** 拆成两栏对比式布局。

**修改后布局：**

```
┌─────────────────────────────────────────────────────────┐
│  01 / 背景与痛点                                          │
│                                                         │
│  标题：科研工作流的核心矛盾                                  │
│  副标题：信息获取极度便利，但信息组织与产出仍在手工作坊模式       │
│                                                         │
│  ┌── 信息端（已解决）──────┐  ┌── 产出端（未解决）──────────┐  │
│  │                        │  │                          │  │
│  │  arXiv 日均 >2,000 篇   │  │  新方向：不知从何读起       │  │
│  │  Zotero 帮我们存文献    │  │  读了 N 篇：无法结构化对比  │  │
│  │  ChatGPT 能回答任何问题 │  │  代码复现：反复踩坑        │  │
│  │                        │  │  实验→论文：中间链路断裂    │  │
│  └────────────────────────┘  └──────────────────────────┘  │
│                                                         │
│  结论：信息过载了，但"处理信息 → 产出成果"的路径没有变短       │
└─────────────────────────────────────────────────────────┘
```

**制作要点：** 左右两栏用不同底色区分（左栏灰绿表示"已解决"，右栏深蓝表示"待解决"）。每栏 3-4 行短句，不要段落。

## 第 3 页 · 痛点拆解

**现状：** "02 / 痛点拆解"，4 个痛点每个一大段描述。

**问题：** 文字太长。每段 4-5 行，4 段堆在一起就是一面文字墙。

**怎么改：** 2×2 卡片布局，每卡片 3 行。

**修改后布局：**

```
┌─────────────────────────────────────────────────────────┐
│  02 / 痛点拆解                                            │
│                                                         │
│  标题：做科研，你的时间花在哪了？                            │
│                                                         │
│  ┌── 01 入门迷失 ────────────┐ ┌── 02 对比疲劳 ───────────┐│
│  │                           │ │                         ││
│  │  导师给了一个新方向        │ │  精读了一周论文           ││
│  │  200 篇论文堆在面前        │ │  回到整体视角时           ││
│  │  不知从哪一篇开始读        │ │  方法、指标、局限         ││
│  │                           │ │  无法结构化对比           ││
│  │  → 信息过载 × 认知空白    │ │  → 碎片阅读 × 缺乏框架    ││
│  └───────────────────────────┘ └─────────────────────────┘│
│                                                         │
│  ┌── 03 复现瓶颈 ────────────┐ ┌── 04 输出断层 ───────────┐│
│  │                           │ │                         ││
│  │  GitHub clone 下来了       │ │  实验数据有了             ││
│  │  配环境 + 调版本 + 修 bug  │ │  想法碎片有了             ││
│  │  比写代码本身还久          │ │  写成论文隔着千山万水      ││
│  │                           │ │                         ││
│  │  → 工程门槛 × 重复踩坑    │ │  → 信息散落 × 整合困难    ││
│  └───────────────────────────┘ └─────────────────────────┘│
└─────────────────────────────────────────────────────────┘
```

**制作要点：** 4 个卡片等大，每个卡片内 3 行场景描述 + 1 行情绪标签。标签用彩色小字（蓝色/红色），不要黑色。

## 第 4 页 · 现有工具局限

**现状：** "03 / 现状分析"，三个工具分析，文字段落。

**问题：** 三列文字太密，缺乏可读性。

**怎么改：** 三列卡片，每列统一结构——工具名 → ✓ 优势（灰色）→ ✗ 缺陷（蓝色高亮）。

**修改后布局：**

```
┌─────────────────────────────────────────────────────────┐
│  03 / 现状分析                                            │
│                                                         │
│  标题：现有工具为什么不够？                                 │
│                                                         │
│  ┌─ 通用 AI ChatBot ───┐ ┌─ 文献管理工具 ───┐ ┌─ 实验追踪工具 ───┐
│  │                      │ │                  │ │                  │
│  │ ✓ 能回答任意问题     │ │ ✓ 能管理引用     │ │ ✓ 能追踪指标     │
│  │ ✓ 能理解论文内容     │ │ ✓ 能分类标签     │ │ ✓ 能记录参数     │
│  │                      │ │                  │ │                  │
│  │ ✗ 无项目级记忆       │ │ ✗ 不分析论文内容 │ │ ✗ 不辅助领域调研 │
│  │ ✗ 输出格式不可控     │ │ ✗ 不做多篇对比   │ │ ✗ 不生成论文段落 │
│  │ ✗ 不能沉淀为资产     │ │ ✗ 不产生研究想法 │ │ ✗ 不关联文献分析 │
│  │ ✗ 跨对话上下文丢失   │ │ ✗ 不跟踪实验     │ │ ✗ 无写作能力     │
│  └──────────────────────┘ └──────────────────┘ └──────────────────┘
│                                                         │
│  结论：每类工具在各自领域优秀，但覆盖的是互相隔离的单个节点        │
│       我们需要一个串联各节点、以项目状态驱动的协作系统            │
└─────────────────────────────────────────────────────────┘
```

**制作要点：** ✓ 用灰色小字，✗ 用蓝色或红色标注。颜色对比让观众不用读文字就能感知"缺点比优点多"。

## 第 5 页 · 方案定位
