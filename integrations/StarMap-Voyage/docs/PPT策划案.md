## 第 2 页：引言 — 问题背景

**页眉标签：** 01 / 背景与痛点

**标题：** 科研工作流的核心矛盾
**副标题：** 信息输入在加速，但信息组织与输出仍在手工作坊模式

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   每周数千篇新论文被发表                                      │
│   文献管理工具（Zotero / Mendeley / Paperlib）帮我们存了文献    │
│   通用 AI ChatBot 能回答任意问题                              │
│                                                             │
│         ───────────── 但 ─────────────                       │
│                                                             │
│   入门一个新方向，面对海量论文仍不知道从哪里读起                 │
│   读了十几篇论文后，无法结构化的对比方法、指标、局限             │
│   论文代码的复现与调试始终是低效循环                            │
│   实验结果和写作输出之间，缺少系统化的衔接桥梁                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**关键话术：**
"信息检索已经高度自动化，但在科研场景中，信息的理解深度、组织结构和创造性发酵，仍高度依赖研究者的个人经验。这造成了从信息到产出的巨大生产力鸿沟。"

**副标题：** 不是又一个聊天机器人，而是为科研全流程设计的结构化 AI 协作系统

```
           领域入门          文献精读          多论文对比
          （概念地图）       （结构化卡片）      （交叉洞察）
              │                │                │

              ┌────────────────┼────────────────┐
              │                │                │
              ▼                ▼                ▼

        （环境+Debug）    （趋势+图表+结论）  （论文+PPT+讲稿）
```

**三个设计原则：**
- **项目中心化** — 所有分析围绕科研项目组织，而非零散的对话

- **人机协同** — AI 提供结构化的分析支持，研究者做出判断与决策

## 第 7 页：AI 调用核心设计 — 双重结构化的安全保障

**页眉标签：** 06 / 核心技术设计

**标题：** 为什么这个系统的 AI 输出是"可控"的？
**副标题：** 大部分 AI 应用输出不稳定，而我们的三层保障机制解决了这个问题

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  第一层：JSON Schema definition (OpenAI Structured Output)       │
│  ─────────────────────────────────────────────────────────────  │
│                                                                 │
│  const overviewJsonSchema = {                                   │
│    name: "overview_report",                                     │
│    strict: true,                 ← 强制严格匹配                  │
│    schema: {                                                   │
│      type: "object",                                           │
│      additionalProperties: false,  ← 拒绝多余字段                │
│      required: ["topic","background","coreConcepts",...],       │
│      properties: {                                              │
│        topic:         { type: "string" },                       │
│        coreConcepts:  { type: "array", items: {type:"string"} },│
│        challenges:    { type: "array", items: {type:"string"} },│
│        // ... 11 个字段，每个字段类型严格定义                     │
│      }                                                          │
│    }                                                            │
│  }                                                              │
│                                                                 │
│  第二层：后端 validate 函数 (服务器端校验)                        │
│  ─────────────────────────────────────────────────────────────  │
│                                                                 │
│  export function validateOverviewReport(value: unknown) {       │
│    // 逐一检查每个字段的类型、必填性、数组元素类型                  │
│    // 任何不匹配 → 抛出 ApiError，不返回脏数据给前端               │
│  }                                                              │
│                                                                 │
│  第三层：前端 assertion 函数 (客户端二次校验)                      │
│  ─────────────────────────────────────────────────────────────  │
│                                                                 │
│  function assertOverviewResult(value: unknown) {                │
│    // 即使后端返回了数据，前端也做最后一层类型守卫                  │
│    // 不通过 → AIServiceError，前端展示友好错误信息               │
│  }                                                              │
│                                                                 │
│  结果：哪怕 LLM 产生幻觉，也不会破坏前端渲染或存储脏数据            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**底部要点（三个标签卡片）：**
- 类型安全贯穿全链路：TypeScript 类型 → JSON Schema → validate → assertion
- 双重校验：前端校验 + 后端校验，任一失败即被拦截
- 降级兼容：http 模式故障时，一键切换 mock 模式保证演示不中断
