# ResearchPilot PPT 演讲稿（全14页，可录制视频）

---

## 第 1 页 · 封面（约 10 秒）

大家好，今天我来分享一个我做的项目——ResearchPilot，一个 AI 科研增效工作台。

简单说，它解决的核心问题是：**从文献综述到论文写作，用 AI 把科研全流程串联起来，形成一个结构化的协作闭环。**

---

## 第 2 页 · 背景与痛点（约 50 秒）

我们先看科研工作流的核心矛盾在哪。

左边是信息端——已经解决了。arXiv 每天 2000 多篇新论文，Zotero 这类工具帮我们管理文献，大模型随时回答各种问题。信息获取的门槛已经降到了历史最低。

但右边——产出端，问题依然在。拿到一个新方向还是不知道从哪篇论文开始读；读了十几篇论文，回到整体视角时，方法、指标、局限无法结构化对比；代码复现永远在配环境和修 bug 之间循环；实验做完了、数据有了，但从数据到论文、从论文到 PPT，中间总有一段说不清的断层。

**结论一句话：信息过载了，但"处理信息到产出成果"这条路径并没有变短。**

---

## 第 3 页 · 痛点拆解（约 40 秒）

我把这些困境拆成四个典型场景，在做科研的同学应该都有共鸣。

**第一个，入门迷失。** 导师给了一个全新方向，200 多篇论文堆在面前。核心概念、主流方法、常用数据集全部空白，不知道该从哪一篇开始读。这就是信息过载撞上认知空白。

**第二个，对比疲劳。** 好不容易读了几十篇论文，但回到整体视角时发现——谁用了什么方法、谁在哪个数据集上更好、各自的局限性是什么，脑子里全是碎片，没有对比框架把它们串起来。

**第三个，复现瓶颈。** 开源代码 clone 下来只是第一步，真正的大头是配环境、调 CUDA 版本、修各种莫名其妙的 bug。花在工程问题上的时间远超花在理解方法上的时间。

**第四个，输出断层。** 实验数据有了、想法碎片也有了，但笔记散落在 Excel、Notion、草稿纸各个地方。从原始数据到论文段落，中间没有一个帮你"组装"的系统。

**这四个困境不是独立的，它们环环相扣，贯穿了科研工作的全部环节。**

---

## 第 4 页 · 现有工具局限（约 50 秒）

那现有的工具能不能解决这些问题？我们分别看一下。

**通用 AI ChatBot**，优势很明显——能回答任何问题，能理解复杂的论文内容。但它致命的缺陷是：没有项目级记忆，聊完就忘；输出格式随意，没法沉淀为可复用的知识资产。而且跨对话上下文丢失，上一轮聊的论文，下一轮就不认得了。

**文献管理工具**，比如 Zotero，能做引用管理、分类标签，但它只做存储——不会分析论文内容，不会做多篇对比，不会产生研究想法，也不跟踪你的实验进度。

**实验追踪工具**，比如 WandB，能精准追踪实验指标，但它聚焦在实验执行阶段，不管前期的领域调研，不管论文写作，跟文献系统也是断裂的。

**结论很明确：每类工具在自己的环节足够优秀，但它们彼此隔离，各管一段。**

我们需要的不是一个更强的聊天机器人，而是一套以项目为中心、贯穿科研全流程的结构化协作系统。

---

## 第 5 页 · 方案定位（约 50 秒）

这就是 ResearchPilot 的定位。

**它不是一个 ChatBot，而是一个围绕五大科研阶段的 AI 工作台。**

这五个阶段是：领域入门，产出概念地图、阅读路线和数据集梳理；文献精读，产出结构化精读卡片和方法拆解；论文对比，产出横向对比表、研究空白分析和新 Idea；实验分析，产出趋势图表和实验建议；写作输出，产出论文段落、PPT 大纲和汇报讲稿。

**三个核心理念支撑整个系统。**

第一，**项目中心化**。所有分析围绕科研项目组织，不是零散的对话，每一次交互都沉淀为项目资产。

第二，**结构化输出**。每个环节产出的都是模板化、可比较、可导出的内容，不是自由文本。你可以把精读卡片放一起对比，可以把报告导出为 Markdown。

第三，**人机协同**。AI 提供结构化的分析支持，但研究者的判断和决策始终在回路里。AI 不替你做决定，它帮你把"做决定需要的信息"组织好。

---

## 第 6 页 · 系统架构（约 50 秒）

这一页是系统的技术架构总览，分三层。

**最上层是表示层**，基于 React 19、TypeScript 6、Vite 8 和 Tailwind CSS 4 构建。六个功能页面通过统一的 `useAsyncGeneration` Hook 管理异步生成的状态——加载中、成功、失败——所有模块共享同一套状态管理模式。

**中间是 AI 服务层**，这是整个架构最关键的抽象。我们用了 Provider 模式——通过一个叫 `aiService` 的统一接口，底下可以切换 mockProvider 和 httpProvider。mock 模式下，规则引擎在前端直接生成结果，零依赖、可独立演示。http 模式下，通过 fetch transport 把请求发到 Express 后端，再调用真实模型。**切换只需要改一行环境变量，代码零改动。**

**最下层是后端服务层**，Express 5 服务器。六大 REST 端点对应六个功能模块，每个模块都有独立的 system prompt、JSON Schema 定义和运行时校验。模型层调用 GPT-4o-mini 的 Structured Output 能力——strict mode、禁止额外字段。还有一个 GitHub REST API Client，代码复现模块会实际抓取仓库的 README 和元数据作为 LLM 上下文，不是凭空生成。

**底部这条虚线框覆盖三层的，是我们的结构化保障链：JSON Schema strict → 后端 validate → 前端 assertion。哪怕 LLM 输出异常，脏数据也到不了用户界面。**

---

## 第 7 页 · 多 Agent 协作设计（约 60 秒）

这一页是这套系统"技术深度"的集中体现。

我们不仅在调 LLM，还在关键环节引入了 **多 Agent 协作架构**。

**三种 Agent 协作协议。**

协议 A——**多 Agent 辩论**。用于论文对比和研究空白分析。不是让一个模型一次性输出结论，而是三个专家 Agent——方法分析者、数据集分析者、理论分析者——各自独立从不同视角分析同一组论文。然后 Critic Agent 交叉审查，找出矛盾和遗漏。最后 Synthesizer Agent 合并所有视角，生成最终的分析报告，并标注每个结论的共识级别。

协议 B——**ReAct 工具调用循环**。Agent 不是只能"想"，它能"做"。当它需要查论文时，调用 arXiv 搜索工具；当它需要理解代码仓库时，调用 GitHub API 工具；当它需要对比实验数据时，调用项目内数据读取工具。它在 Thought → Action → Observation 之间循环，直到完成目标或达到步数上限。

协议 C——**自反性精炼**。用于写作输出和 Idea 生成。生成初稿 → Critic Agent 从逻辑连贯性、论据充分性、术语准确性、可读性四个维度打分并给出修改建议 → 修订 Agent 针对性修改 → 最多迭代三轮。当所有维度达到 7 分以上或者连续两轮无显著改进时自动停止。

**中间这层是六个专家 Agent——文献分析、方法分析、实验分析、批判审阅、写作生成、综合汇总。每个 Agent 都有独立的 system prompt、专属的 tool 集合和类型守卫输出。**

**底部是基础设施层：Tool Registry 管理所有可用工具，OpenAI SDK 统一调用模型，Output Guard 三层保障链确保输出可靠。**

## 第 8 页 · 功能模块（一）领域快速入门（约 40 秒）

接下来我们快速过一下四大功能模块。

**第一个，领域快速入门。**

你需要做的非常简单——输入你的研究方向，一句话就够了，比如"AI 科研增效工具设计"。可选地补充一些具体需求。

AI 在背后完成结构化处理——生成四组领域报告。

第一组**基础认知**：领域背景概述、核心概念列表，帮你快速建立认知框架。

第二组**研究版图**：梳理主要研究任务、主流方法和当前挑战，让你看到这个领域的全貌。

第三组**数据与评估**：列出常用数据集和评价指标，后续做实验选 benchmark 直接用。

第四组**切入与路线**：挖掘潜在研究方向和空白点，给出建议的阅读路线——先读什么综述、再看什么 baseline、最后追踪什么前沿工作。

所有报告一键保存到项目，支持导出 Markdown。

---

## 第 9 页 · 功能模块（二）文献精读 + 论文对比（约 50 秒）

**文献精读。** 你输入论文标题、摘要和关键词，AI 自动生成一个 9 维精读卡片——研究背景、Motivation、核心问题、方法框架、创新点、实验设计、数据集、评价指标、优点。还会给出局限性和对你自己项目的启发。

卡片右上角有一个很实用的功能——**系统自动判断这篇论文是否适合作为你的 Baseline 候选**。不用你自己一篇篇去评估。

**多论文对比。** 当你项目里积攒了几篇精读卡片之后，勾选 2 到 6 篇，系统会做两件事。

第一，生成一张**逐维对比表**——Motivation、方法、创新点、数据集、评价指标、优点、局限、启发，全部横向对齐。你一眼就能看出论文之间的差异和共性。

第二，生成一份**研究空白分析**。包括共性问题总结、数据与方法缺口、可转化研究问题，以及自动生成的 Research Idea 卡片——每张卡片附带新颖性、可行性、工作量三个维度的评分。这是帮你从"读论文"到"找到自己的研究选题"的关键跨越。

---

## 第 10 页 · 功能模块（三）代码复现 + 实验分析（约 50 秒）

**代码复现辅助。** 这个模块有一个关键设计——不是靠 LLM 凭空猜测一个 GitHub 仓库的内容，而是**实际调用 GitHub REST API** 去抓取仓库的 README 文件和元数据（描述、语言、主题标签），再把这些真实内容作为上下文喂给 LLM 进行分析。

输出四个方面：README 分析摘要，帮你提取环境要求、数据准备方式和运行命令；可执行的环境配置命令序列；针对报错日志的分类 Debug 建议；以及从环境验证到数据准备到训练基线到评估验证的四步执行路线。

**实验结果分析。** 输入实验名称和原始结果文本，AI 自动分析趋势、识别最优方法、标注异常值、给出可能原因和补充实验建议。还会生成一段可以直接写进论文的实验结论。

最有特色的是**图表建议**——系统不仅告诉你该用什么图表类型、X 轴 Y 轴怎么定义、突出什么对比关系，还会生成一段可以直接运行的 matplotlib 代码。你复制到 Jupyter Notebook 里就能出图。

---

## 第 11 页 · 功能模块（四）写作输出 + 成果管理（约 40 秒）

**写作输出。** 支持六种写作类型——论文 Introduction、Related Work、Method、Experiment、PPT 大纲和答辩讲稿。输入写作类型和你的补充要求，AI 一次性生成三样东西：一段流畅的学术论文段落、一份逐页 PPT 大纲、一份页间衔接的讲解稿。三合一输出，你做汇报的时候直接就能用。

**成果管理。** 之前所有模块的产出——领域报告、论文卡片、实验记录、写作草稿、研究 Idea——都汇总在同一个项目级知识库里。按类型聚合展示，每条记录支持查看详情、导出 Markdown、删除。

**三个核心能力：统一视图，按类型聚合所有成果；一键导出，任意成果导出为 .md 文件；全项目汇总，把整个项目的知识资产打包导出。**

---

## 第 12 页 · 工程落地（约 40 秒）

聊完了功能，说一下工程层面的实际落地。

**技术栈方面**，前端 React 19、TypeScript 6、Vite 8、Tailwind CSS 4，全部最新版本。后端 Express 5 提供 RESTful API，模型层对接 OpenAI Structured Output 和 GitHub REST API。整个项目 60 多个源文件，4000 多行 TypeScript，零 Warning 编译通过。

**我想特别强调三个"不是而是"。**

**不是 ChatGPT 聊天框套壳。** 六个独立模块，每个都有完整的输入、AI 处理、结构化输出、保存到项目、导出 Markdown 的全业务链路。

**不是 Mock 数据假演示。** 双 Provider 架构——Mock 模式可以在无网络环境独立演示所有功能，HTTP 模式一行配置就能切换为真实 GPT-4o-mini 驱动。

**不是前端玩具。** 前后端分离架构、Express 后端提供标准的 RESTful API、JSON Schema 严格校验、前后端类型守卫双重保障，这是一套具备生产级思考的全栈系统。

## 第 13 页 · 现场演示（约 30 秒过渡 + 演示时间）

接下来是现场演示环节。

我的演示会覆盖五个关键步骤：首页展示科研闭环流程概念；打开项目看仪表盘的指标总览和系统自动生成的下一步建议；领域入门和文献精读的实际操作——输入研究方向实时生成报告、输入论文信息生成精读卡片；选两篇已保存的论文做对比分析，生成对比表和研究空白；最后展示写作输出和成果管理，以及切换 Provider 模式的兼容性验证。

如果现场网络或环境出问题，我也准备了提前录好的演示视频作为 Fallback。

## 第 14 页 · 总结（约 40 秒）

最后总结一下。

ResearchPilot 做的事情可以归纳为三个关键词。

**结构化**——把科研从离散的单次问答，变成持续沉淀的结构化工作流。每一环都有固定的输入输出格式，每一次交互都有迹可循、可比较、可复用。

**全闭环**——从领域入门到文献精读、从论文对比到实验分析、从代码复现到写作输出，覆盖了科研工作者的完整工作流。AI 全程参与但不替代研究者的判断。

**零鸿沟**——Mock 模式可以零依赖演示，HTTP 模式对接真实模型。演示和产品之间没有鸿沟——你看到的演示，就是可以实际部署和使用的系统。
