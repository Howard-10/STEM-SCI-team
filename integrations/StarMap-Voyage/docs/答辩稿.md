# Research-Copilot-OS 答辩稿

> 总时长: 约 20 分钟 | 12 页 PPT

---

## Slide 1: 封面 (30秒)

各位老师好，我今天汇报的题目是 **Research-Copilot-OS——AI 赋能科研全流程智能平台**。

这个平台整合了 19 个 AI 工具，由 DeepSeek V4 大模型驱动，通过四大引擎协同工作，覆盖从文献阅读、代码分析、数据处理到实验管理的完整科研闭环。接下来我将从动机、架构、功能实现和创新点几个方面展开介绍。

---

## Slide 2: Motivation — 科研工作者的真实痛点 (1.5分钟)

在开始介绍平台之前，我想先谈谈科研工作中三个普遍存在的痛点。

**第一个痛点：文献阅读耗时。** 每天都有大量新论文涌现，逐篇阅读效率非常低。更麻烦的是，当你需要对比几篇论文的方法和实验结果时，往往要来回翻看，手动做笔记，非常耗时。

**第二个痛点：代码理解困难。** 论文附带的代码结构往往很复杂，想要快速理解一个陌生项目的架构、找到可以迁移到自己模型里的亮点模块，目前基本靠人工阅读和手动复制粘贴，没有自动化工具。

**第三个痛点：实验管理混乱。** 超参数调优靠经验、消融实验靠手工注释代码、数据增强和可视化的代码每次都要重写。这些重复性工作占用了大量本该用于思考的时间。

基于这些痛点，我们产生了这个平台的核心设计理念——**打造一个覆盖「读论文→懂代码→做实验」全流程的 AI 科研助手**。

---

## Slide 3: 整体架构 — 四大引擎 + Agent 智能体 (2分钟)

平台的架构分为两层：引擎层和 Agent 层，共四个核心引擎。

**文献理解引擎**负责 PDF 的解析和论文的深度解读。我们用了多策略 PDF 解析管线——PyMuPDF + pdfplumber 组合——来处理各种质量的论文 PDF。在上面用 RAG 检索增强和 LLM 深度分析实现单篇论文的结构化解读和多篇论文的综述对比。

**代码分析引擎**基于 Python AST 静态分析，能自动识别 PyTorch 项目中的模型定义、前向传播、训练循环等代码块，并支持将一个项目中的亮点模块迁移到另一个项目中，自动对齐维度。

**实验编排引擎**处理数据集适配、数据增强、消融实验和超参数调优。

**可视化生成引擎**能够学习研究方向的可视化范式，自动生成符合学术规范的图表。

在引擎层之上是 **AI Agent 智能体层**——这是平台的大脑。它拥有 19 个标准化工具，采用了类似 Claude Code 的 Think-Act-Observe 循环模式，加上 4 项领域专项技能，并且有完整的权限控制系统来保证操作安全。

---

## Slide 4: 技术架构 (1分钟)

技术栈从下到上分为五层。

最底层是 **LLM 层**，我们使用 DeepSeek V4 的 deepseek-chat 模型，通过 OpenAI 兼容接口调用，支持结构化 JSON 输出和 Function Calling。

**引擎层**用了 PyMuPDF + pdfplumber 做 PDF 解析，Python AST 做代码分析，PyTorch 的 torchvision 做数据增强的实时执行，SQLite 做实验记录存储。

**Agent 层**实现了 Claude 式的编排器，包含技能系统、权限控制器、会话管理，并且多论文分析采用了并行处理。

**API 层**基于 FastAPI，有 40 多个 REST 端点，支持异步处理和文件上传。

最上面是 **前端层**，使用 Streamlit 构建，采用深色主题和响应式布局，四大模块通过顶部导航栏切换，侧边栏固定为 AI 助手。

## Slide 5: 功能 1 — 文献整理与解读 (2分钟)

这是平台的第一个核心功能模块。分为两部分。

**单论文深度解读**：用户上传 PDF 后，平台先用多策略管线提取文本——先试 PyMuPDF layout 模式，再试 dict 模式加位置排序，最后试 pdfplumber。取质量评分最高的结果。然后全文一次性发送给 DeepSeek，让它做五个维度的分析：动机与背景、方法论深度（包括模型架构、算法流程、关键创新点和公式解读）、实验全面分析（数据集、指标、主结果、消融、对比、效率）、深度评价（优势、局限、说服力、可复现性）。还支持文本质量预检和强制读取模式——对于扫描版 PDF 也能尽量提取信息。

**多论文综述对比**：多篇论文采用并行分析，用 ThreadPoolExecutor 同时处理。分析完成后，自动做分类聚类，然后进行模块对模块的对比——22 个字段逐一对应，包括问题定义对比、架构对比、算法对比、创新点对比、数据集/指标/结果/消融/效率的全面对比。最后输出对比表格、综述报告和论文关系图谱。每篇论文都有完成度评分，标注 success、partial 或 failed。

---

## Slide 6: 功能 2 — 模型融合 (2分钟)

模型融合模块包含代码分块和模块迁移两个子功能。

**代码分块**基于 Python AST 静态分析。我们定义了一套关键词映射规则，能自动识别 PyTorch 项目中的 nn.Module 子类、Dataset、DataLoader、Loss Function、Optimizer、训练/验证循环等。每个代码块提取完整的源代码，并标注文件路径和行号。在此基础上，用 LLM 做语义增强，将代码块归入六个顶层类别——参数配置、模型架构、数据处理、训练优化、评估日志、工具入口。支持 zip 上传、本地路径输入和历史缓存三种方式。

**智能模块迁移**是整个平台最有特色的功能之一。它有两种使用路径：一是从历史分块中选择模块，二是双项目实时对比。界面采用左右分栏布局——左边是源项目的可迁移模块，右边是目标模型按 forward 顺序排列的有序分块。操作流程是：点击选源模块→点击目标模型的插入位置→AI 自动对齐→预览→保存。保存前生成维度适配代码，并对梯度连续性、维度匹配、训练稳定性做风险评估。原文件自动备份为 .bak。

还有一个亮点功能是**代码块 AI 解读**。分块完成后，每个代码块旁边有一个按钮，点击后 AI 会解读这个块的用途和它跟上一个块的连接关系。Agent 在分块时已经预读了全部代码，所以回答有全局视野。

## Slide 7: 功能 3 — 数据处理 (1.5分钟)

数据处理模块同样分为两个子功能。

**数据集自动适配**：用户可以输入数据集路径（文件或文件夹），平台自动检测格式并进行采样分析——识别数据格式、样本数量、特征维度、标签类型、类别数。更好的是，用户可以上传模型代码的 zip 包，平台会自动提取其中与数据处理相关的代码（Dataset 类、DataLoader 创建、输入维度定义等），然后基于这些信息生成完全适配的 DataLoader 代码。

**包装化数据增强与攻击**：这是平台中交互性最强的功能之一。总共支持 20 种操作，涵盖几何变换、色彩变换、模糊化、噪声注入、高级增强（MixUp、CutMix、CutOut、RandAugment）和数据攻击（FGSM、PGD）。工作流程分为四步：第一步选择操作（按类别折叠展示，每组支持全选）；第二步单图测试——上传一张图片，实时预览增强前后的对比效果；第三步批量处理——指定文件夹，所有图片处理后按操作名称分目录保存；第四步自定义增强——可以通过 AI 交互描述需求，或者直接生成可集成到项目中的 Python 代码。

---

## Slide 8: 功能 4 — 实验模块 (2分钟)

实验模块包含四个子功能，覆盖了实验管理的完整流程。

**可视化工作自动化**：这是我认为最有意思的功能。AI 能够根据已分析的论文内容推荐合适的图表类型——比如从论文中提取出使用了哪些评估指标、哪些数据集，然后推荐对应的对比柱状图、雷达图、t-SNE 可视化等。用户可以用三种方式输入数据：文本描述、上传 CSV 文件、直接粘贴。然后 AI 进入迭代生成模式——生成代码、执行出图、五维评分（数据清晰度、标签标题、配色美观、科研规范性、完成度）、根据反馈修缮代码、重新出图，循环直到评分达到 90 分以上。所有图表使用 Morandi 学术配色方案。

**消融实验智能包装化**：上传项目后，AI 按两个条件筛选可消融模块——拆卸后不影响全局、是模型的创新点。然后列出每个模块的所有出现位置，确保消融时不遗漏任何一处。用户勾选后，AI 自动移除代码并对断开处做维度对齐。修改后的代码可以预览，确认后才保存。

**超参数调优**：支持三种代码输入方式。AI 会识别所有显式和隐式的超参数，对每个参数展示当前值、建议范围和调整影响。更好的是，用户可以描述训练过程中遇到的问题——比如"loss 在第 50 个 epoch 后不再下降，验证准确率在 75% 波动"——AI 会诊断问题并给出具体的调参建议，标注优先级。

**实验记录**：所有实验的超参数和测试指标自动存入 SQLite 数据库，支持搜索筛选和 epoch 级别的折线图查看。

## Slide 9: AI Agent 智能体系统 (1.5分钟)

Agent 是平台的核心"大脑"，有四个关键特性。

**Claude 式的 Think-Act-Observe-Reflect 循环**：Agent 不是简单的单轮问答。它先思考需要哪些工具、按什么顺序调用，然后执行工具、观察结果、反思是否需要调整方案。这个循环最多进行 8 轮，保证了复杂任务的处理能力。底层用的是 DeepSeek 的 Function Calling 接口，和 Claude 的工具调用协议在本质上是一样的设计模式。

**19 个标准化工具**：包括 6 个系统工具——Read、Write、Edit、Glob、Grep、Bash——让 Agent 能像人类开发者一样操作文件系统和执行命令；以及 13 个科研专用工具——论文解读、代码分块、模块迁移、数据集适配、数据增强、可视化生成、消融实验、超参数识别等。

**4 项领域技能**：技能系统是我们为 Agent 设计的一套专项工作流。每个技能定义了自己的触发词、推荐工具集和 SOP 步骤。当用户输入匹配某个技能的触发词时，对应的 SOP 工作流会注入到 LLM 的 System Prompt 中，让 Agent 严格按照专业流程执行。这大大提高了输出的稳定性和质量。

**权限控制**：只读操作自动允许、项目目录内的写入自动通过、危险命令（如 rm -rf、sudo、curl|sh）自动拦截。API 层面还有路径穿越防护和 ZIP 攻击拦截。

## Slide 10: 创新点总结 (1分钟)

我总结了六个创新点。

**全流程覆盖**：从文献阅读到实验管理的完整闭环。目前市面上有单一功能的工具——比如 Zotero 管文献、GitHub Copilot 写代码、TensorBoard 看训练——但没有一个平台能把这些环节串起来。Research-Copilot-OS 填补了这个空白。

**Claude 框架 + DeepSeek 模型**：我们复用了成熟的开源 Agent 设计模式，但底层的推理引擎用的是国产的 DeepSeek V4。这意味着用户不需要 Anthropic 的 API Key 就能使用 AI 科研助手，成本更可控。

**模块对模块对比综述**：传统的文献工具只能做单篇摘要。我们把每篇论文拆成 22 个结构化字段，然后进行逐模块的横向对比，输出的是可以直接用于写 Related Work 的综述报告。

**可执行的操作闭环**：平台不只是给你分析建议——代码分块之后可以直接迁移模块，消融实验方案可以直接执行代码修改，数据增强方案可以实时预览效果。分析→决策→执行，在同一个平台内完成。

**技能系统**：4 项领域 Skill 让 Agent 的行为更精准、输出更稳定。这比单纯的 Prompt Engineering 更进一步——它是一套结构化的 SOP 注入机制。

**安全与鲁棒**：从 API 层的路径穿越防护、ZIP 攻击拦截，到 Agent 层的危险命令过滤和原文件自动备份，平台在每个层面都做了安全加固。

## Slide 11: 总结与展望 (1分钟)

总结一下已完成的工作：四大引擎全部实现并通过了测试，40 多个 API 端点，完整的 Streamlit 前端界面，19 工具的 AI Agent 和 4 项技能系统。每个功能模块都经过了多轮迭代和 bug 修复。

展望未来，有几个方向值得继续推进：接入 OCR 策略来处理扫描版 PDF；实现更直观的拖拽式代码模块交互；集成训练过程的实时监控，让 Agent 能根据 loss 曲线动态给出调参建议；支持更多模型后端；以及最终的目标——让 Agent 能够根据实验结果自动撰写论文初稿。
