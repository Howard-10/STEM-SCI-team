# STEM-SCI 申报要求与验收矩阵

> 依据：XH-202620《面向一流学科建设的学科垂类大模型与创新应用开发》
>
> 用途：把申报要求转换成可演示、可测量、可提交的交付项。状态只描述当前仓库证据，不代表申报方已经完成外部用户验证。

## 产品边界

STEM-SCI 的产品表述应为“研究者主导、AI 协助的 STEM 教育科研助研系统”。系统可以自动检索、整理、生成候选方案和准备分析，但研究者必须确认研究问题、证据充分性、研究方案、数据处理、代码执行和最终发布。

以下内容不能作为已完成能力宣传：未核验外部题录、未复现的原论文统计结果、模型自动生成的实证结论、未经用户试用验证的节省时间或准确率。

## P0 验收门槛

1. 三个黄金案例均能从对话入口开始，并在每个关键节点留下研究者决定。
2. 检索 Gold Set 完成两名独立标注和争议仲裁后，才报告 Recall@k、MRR 或 nDCG。
3. 论文候选稿中的每个结果主张都能回到冻结数据、执行记录或来源核验记录。
4. 至少完成两名真实教师/研究生试用；用户数据必须取得授权并脱敏。
5. 申报包包含产品 Demo、技术说明、用户手册、安全承诺和效果验证报告。

## 黄金案例

### 案例 A：文献证据链

输入研究主题，完成本地知识库和外部发现，输出候选论文、原文证据、来源定位、研究空白和人工确认记录。

### 案例 B：STEM 研究设计

输入“生成式 AI 分层支架对师范生 Python 物理建模和无辅助迁移的影响”，输出研究问题、任务 A/B/C、变量、测量、样本量、预注册草案和风险清单。

### 案例 C：数据分析与写作

输入经授权的脱敏数据和冻结方案，完成数据审计、代码审查、受限执行、结果验证、稳健性检查和论文候选稿。没有真实数据时只能演示数据链路，不能宣称研究效果。

## 近期执行顺序

1. 冻结三个案例和通过标准；
2. 完成检索 Gold Set 双人标注；
3. 运行离线评测并生成基线报告；
4. 增加用户试用日志和反馈表；
5. 生成效果验证报告和申报材料；
6. 最后再扩展完整论文写作和图表生成。
