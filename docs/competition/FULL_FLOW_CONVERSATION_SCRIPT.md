# STEM-SCI 对话式全流程测试脚本

## 先说明测试模型

本项目保留 28 个可审计的科研操作，但它们不是 28 次用户点击，也不是 28 段必须手工输入的对话。系统应自动完成内部检索、重排序、规范化、验证和产物记录；研究者只在有研究判断、数据治理或发布责任的边界作决定。

因此，本文件有两种用途：

1. **用户验收**：按下方 12 个对话检查点测试。
2. **内部审计**：在每个检查点后，从右侧“研究产物/可追溯性”查看对应内部操作是否产生了可读产物。不要要求用户逐项批准 BM25、RRF、Bootstrap 等内部操作。

## 测试材料

- 文献：`D:/揭榜挂帅psy/STEM-SCI/test_data/stem_ways_thinking_2025.pdf`
- 数据：`D:/揭榜挂帅psy/STEM-SCI/test_data/sphere_fci_quantitative.csv`
- 路线：观察性定量的公开二手资料再分析。

## 用户验收：导师式澄清 + 12 个研究检查点

### 1. 创建项目、上传 PDF、共同澄清研究意图

新建项目后上传 PDF，发送：

```text
我想开展一项公开二手资料再分析。主题是：公开 SPHERE FCI 数据中，不同性别编码组的物理概念理解得分是否存在描述性差异。我目前还不确定最合适的研究问题和分析边界，希望你像导师一样一步一步和我澄清。
```

**应看到：** 系统先不检索、不定路线、不进入研究设计；它依次询问研究目标、关注对象/现象、预期贡献、已有资料与数据、方法与解释边界、现实约束。每次只问一个问题，允许回答“不确定”。

回答完后，系统应展示研究简报，而不是立即推进。检查其中是否清楚写出公开二手资料、`group`、`transfer_score`、观察性描述和非因果边界。

确认后发送：

```text
确认研究简报，开始检索。
```

**应看到：** 这时才自动完成文献规范化、BM25/向量/图谱候选、RRF、重排序和主张—证据判断，并进入证据共读。

### 2. 测试一次补充检索

在证据充分性对话中发送：

```text
当前证据还不够。请补充检索“physics concept inventory gender difference observational study”和“FCI validity physics education”，只增加新的候选，并告诉我新增了多少篇；没有新增也要说明检索源、查询范围和原因。
```

**应看到：** 系统把它理解成“继续检索”，而不是跳进研究设计；新增数量或零结果原因清楚可见。

### 3. 确认证据充分，选择研究问题

发送：

```text
我已审阅证据包。当前文献足以形成公开二手资料的观察性研究问题；保留未核验外部来源不能进入正式结论的限制。请提出研究问题候选。
```

看到候选后发送：

```text
选择第 1 个研究问题：只比较公开样本中 group 与 transfer_score 的描述性差异，不作因果解释。
```

**应看到：** 这是自然语言共同设计检查点，不应出现内部 Agent 选择器。

### 4. 审阅并确认研究设计

发送：

```text
请展示研究设计：分析单位、group、transfer_score、纳入排除范围、主要分析、探索性分析，以及观察性设计的解释边界。我先审阅，不冻结。
```

通过后发送：

```text
我确认采用该观察性设计：主要分析是冻结公开样本中 group 与 transfer_score 的两组描述性比较；不自动加入协变量，也不解释为因果效应。
```

**内部审计：** 研究设计、DAG 适用性判断和功效/敏感性说明均已生成；已有公开样本的功效结果不得被伪装成招募依据。

### 5. 冻结预注册候选

发送：

```text
我确认冻结本次预注册候选。后续如果修改数据、变量、筛选或模型，必须生成新版本，并使旧的下游结果标记为过期。请进入原始数据导入。
```

**应看到：** 冻结是一个明确的人类审批，版本不可被原地改写。

### 6. 上传原始数据并请求审计

上传 CSV，随附件发送：

```text
这是公开 SPHERE FCI 数据派生的 CSV。请登记来源，并审计字段、行数、缺失、重复和异常；审计前不要修改数据，也不要把它视为我新采集的实验数据。
```

**应看到：** 数据仍是候选版本，审计显示字段和风险；`group` 与 `transfer_score` 被识别。

### 7. 审阅审计并冻结数据

发送：

```text
我已审阅数据审计。允许无损、可追溯的数据准备，不得删除记录、改写 group 或 transfer_score。请展示冻结候选及其行数、字段和数据指纹。
```

通过后发送：

```text
我确认冻结当前数据版本用于本次分析。请生成分析代码候选并完成静态审查，但先不要执行。
```

### 8. 审阅代码并批准执行

发送：

```text
请用自然语言概述分析代码、读取的冻结数据、两组比较规格、静态安全检查和代码审查结果。没有适用的公式、单位或约束检查时请明确写不适用。
```

通过后发送：

```text
我已审阅代码候选和静态检查。批准在受控沙箱中执行冻结数据上的两组描述性比较，并保留代码版本、数据版本、执行环境和日志。
```

### 9. 审阅结果解释边界

系统会自动执行统计验证、Bootstrap、置换检验、方向一致性和不确定性判断。发送：

```text
请展示结果卡：两组样本量、均值、差异、区间、效应量和适当统计量；同时说明哪些结论能支持，哪些因观察性设计而不能声称。
```

通过后发送：

```text
我确认结果只能作为公开二手资料的观察性描述。请保留不确定性和不能作因果解释的限制，进入论文大纲。
```

### 10. 确认论文大纲，生成候选正文

发送：

```text
请先展示论文大纲和主张—证据表。每个正式主张都要能回到已核验文献或冻结结果；未核验外部题录只能作探索性背景。
```

通过后发送：

```text
大纲可以。请按该大纲生成候选论文正文和引用核验清单，不要把它标成已投稿或最终发表版本。
```

### 11. 审阅不确定性与引用核验

发送：

```text
我已审阅候选稿。请列出不确定性、无法支持的结论和仍需人工核对的引用信息；不要把警告藏在技术日志里。
```

**应看到：** 不确定性 Gate 是结论边界确认，不是要求用户了解内部系统术语。

### 12. 独立审稿人最终确认

用不同于研究者的 reviewer 账号核对研究问题、冻结数据、代码、结果、主张和引用，之后确认最终审稿包。

**通过标准：** 研究者本人不能完成独立审稿；项目在 reviewer 确认后才可进入 `COMPLETED`。

## 内部算子审计表

| 用户边界 | 应在右侧可检查的内部产物 |
| --- | --- |
| 证据充分性 | 规范化文献、混合检索、RRF、重排序、主张—证据判断、证据包 |
| 研究设计/预注册 | 研究问题、研究设计、DAG、功效/敏感性说明、预注册候选 |
| 数据冻结 | 原始数据登记、审计、处理计划、冻结版本和哈希 |
| 执行许可 | 代码候选、AST、公式/单位/约束适用性、代码审查 |
| 结果解释 | 沙箱运行、统计验证、Bootstrap、置换、方向一致性、结果卡、不确定性 |
| 写作与审稿 | 论文大纲、候选正文、引用核验、主张追溯、最终审稿包 |

## 记录为缺陷的情况

- “继续搜索”被理解为进入研究设计，或系统假装新增了文献；
- 外部题录被当作已经核验的正式证据；
- 未经确认就冻结数据、执行代码或通过最终审稿；
- 对话暴露 `document://`、哈希、`segment-*` 或大段内部 JSON，而没有可读解释；
- 冻结版本被覆盖，或上游修改后下游代码、结果、主张没有标为过期；
- 观察性数据被表述为因果结果；
- 定性路线被误判为必须运行统计链路，或量化路线遗漏统计验证。
