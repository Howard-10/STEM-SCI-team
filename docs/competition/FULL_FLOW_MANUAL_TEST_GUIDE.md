# STEM-SCI 完整流程人工测试指引

> 目标：验证“研究者主导、AI 协助”的观察性定量再分析主路径。
>
> 本次用公开 SPHERE FCI 数据测试平台功能，不把结果描述为新的因果发现。

| 类型 | 文件 |

CSV 有 497 行公开二手资料。`group` 是公开性别编码的派生分组，`transfer_score` 是按公开 FCI key 计算的正确题数。它只用于流程验收和描述性关联分析。

## 1. 新建项目

新建项目，不要复用已完成项目。

| 字段 | 填写内容 |
|---|---|
| 项目名称 | SPHERE FCI 物理概念理解公开再分析（手工测试） |
| 研究方向 | 使用公开 SPHERE FCI 数据，比较不同性别编码组的物理概念理解得分；仅做描述性关联分析，不作因果结论。 |

上传 PDF：`stem_ways_thinking_2025.pdf`。此时不要上传 CSV。

## 2. 启动：第一次在对话框发送

```text
我想开展一项公开二手资料再分析。请把已上传的 STEM 物理教育论文作为文献依据，先检索本地知识库和外部公开题录，整理可定位证据并说明研究空白。研究问题是：公开 SPHERE FCI 数据中，不同性别编码组的物理概念理解得分是否存在描述性差异？我只做观察性描述，不作因果结论。请先完成文献整理和证据规范化，再把可审阅的证据包给我。
```

### 应检查

- 路线应是“观察性定量”或等价描述，不应识别为随机实验。
- 右侧应出现文献/证据摘要，包含来源数、原文片段数、外部候选数和研究空白。
- 外部搜索论文只能显示为“候选”，不能自动计为正式证据。
- 对话应停在“证据充分性审阅”而不是要求逐个批准内部 Agent。

### 通过后发送

```text
我已查看证据包。当前文献足以形成一个公开二手资料的观察性研究问题；保留“不能作因果解释”的边界。请进入研究方案和预注册草案。
```

## 3. 研究方案与预注册检查点

系统会自动整理研究问题、变量、分析边界、DAG/功效适用性判断和预注册候选。对于此公开二手资料，功效分析若提示不适用或仅供参考是正确的，不能伪装成新实验的样本量设计。

### 应检查

- 主要分组变量为 `group`，主要结果变量为 `transfer_score`。
- 方案写明“观察性”“公开二手资料”“描述性关联”。
- 不能出现“干预导致”“提升效果”“随机分配”等词。
- 预注册候选应将后续分析限制为两组描述性比较，并保留修改须产生新版本的说明。

### 通过后发送

```text
我确认研究问题、变量和分析边界：以 group 分组、transfer_score 为结果，仅比较冻结公开样本中的两组描述性差异；不解释为因果效应。请冻结预注册候选并进入原始数据导入。
```

## 4. 原始数据导入检查点

当系统提示“导入原始研究数据”时，使用对话框附件上传：

```text
D:/揭榜挂帅psy/STEM-SCI/test_data/sphere_fci_quantitative.csv
```

随附件发送：

```text
这是公开 SPHERE FCI 数据派生的 CSV。请只审计字段、缺失、重复、异常和可执行性；不要在审计前修改数据，也不要把它视为我新采集的实验数据。
```

### 应检查

- CSV 只能在此阶段允许上传；若前面上传，系统应明确阻止。
- 审计结果应列出字段、行数、缺失和重复检查。
- 系统应保留原始数据版本和哈希，不应直接改写原始文件。

### 通过后发送

```text
我已审阅数据审计。允许执行无损、可追溯的数据准备；不得删除记录、改写 group 或 transfer_score，所有处理必须生成新版本并保留审计记录。
```

## 5. 数据冻结检查点

系统会生成处理后的候选版本和数据哈希。

### 应检查

- 明确显示冻结版本、行数、字段和数据指纹。
- 冻结后修改应产生新版本，而不能覆盖旧版本。
- `group` 与 `transfer_score` 必须仍存在。

### 通过后发送

```text
我确认冻结当前处理版本用于本次两组描述性比较。任何数据、变量或筛选规则修改都必须创建新版本并使下游代码和结果失效。请生成分析代码候选并完成静态审查。
```

## 6. 代码与人工执行检查点

系统应生成 Python 分析候选、执行前审查和物理/安全检查。代码生成服务可以是 Codex，也可以退回确定性模板；重点是候选代码不能自行执行。

### 应检查

- 代码只读取冻结数据，不读取网络或任意本地路径。
- 分析明确为 `mean(transfer_score) by group` 或等价两组描述性比较。
- 有代码哈希、静态审查和人工执行许可。
- 若显示 `PYTHON_ONLY`，必须如实显示，不能称为 SPSS/Python 双引擎验证。

### 通过后发送

```text
我已审阅代码候选和静态检查。批准在受控沙箱中执行冻结数据上的两组描述性比较，并要求保留执行环境、代码版本、数据哈希、Bootstrap、置换检验和方向一致性记录。
```

## 7. 结果、不确定性与论文检查点

系统将执行分析，自动完成统计结果验证、Bootstrap、置换检验、方向一致性和不确定性判断，然后生成统计结果卡和论文候选稿。

### 应检查

- 结果卡应有样本量、两组均值、均值差、置信区间、效应量和 p 值或明确的不确定性说明。
- 结果的每个数值必须能回到冻结数据和执行记录。
- 论文只可写“公开二手资料的观察性描述”，不能写“性别导致得分变化”。
- 论文引用应回到已核验来源；外部题录未核验时不能成为正式结论依据。

### 通过后发送

```text
我已审阅结果卡、不确定性提示和论文候选稿。保留观察性、公开二手资料和单引擎分析边界；请生成最终审稿包，供独立审稿人核对研究问题、证据、数据、代码、结果和主张。
```

## 8. 独立审稿人最终确认

此步需要不同于研究者的 reviewer 账号。研究者本人不应能通过“独立审稿”。

审稿人核对：

1. 研究问题、数据和方法一致；
2. 结果数值可回链到冻结数据和执行记录；
3. 结论没有超过观察性设计；
4. 引用作者、年份、定位和主张范围准确；
5. 论文标注为候选稿，未伪装成已投稿终稿。

审稿人确认后，项目应显示 `COMPLETED` 或“完成，待发布归档”。

## 失败即记录

下列任意情况均记为 Bug，不要为了推进测试而跳过：

- “继续搜索”被误解为进入研究设计；
- 外部题录被当作已核验正文证据；
- 未确认时自动冻结数据或执行代码；
- 对话框中显示哈希、内部资料 URI 或大量 JSON；
- 数据修改覆盖旧冻结版本；
- 观察性数据被写成因果结论；
- 研究者账号能完成独立审稿；
- 执行失败后没有明确失败原因和重试/返工入口。
