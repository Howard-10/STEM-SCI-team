# 高中物理教师整合计算思维与 Python 教学的专业学习需求

## 一项证据约束、可执行的定性研究方案

### 摘要

本研究考察高中物理教师将计算思维与 Python 纳入既有物理课程时的专业学习需求。它不是对“是否学习 Python”的泛泛调查，而是追踪教师如何把计算实践、物理建模和课堂教学法连接为可实施的教学决策。方案以已导入的 Lane、Galanti 与 Rozas（2023）为起点：该文将物理教师的计算整合描述为一种“再新手化”过程，并提出从计算知识、物理中的计算应用到物理-计算教学法知识的路径。该文的 24 名工作坊参与者和问卷结果属于**来源研究**，不是本项目的样本或发现。

本项目拟采用最大差异目的性抽样，收集背景问卷、半结构式访谈、课后反思和去标识化教学设计材料。资料版本、数据处理范围和分析规则在解释前冻结；主题分析保留代码定义、反例、片段定位与独立复核记录。当前文稿是待审批的研究方案，未报告参与者数据、主题频数、教学效果或因果结论。

**关键词：** 高中物理；计算思维；Python；教师专业学习；再新手化；定性主题分析

## 1. 问题与研究缺口

计算思维在学科教学中的价值，取决于它是否被转化为可执行的学科实践，而不是是否额外开设一门编程课。Lane 等将高中物理中的计算整合界定为学科情境化的计算，并指出教师需要同时处理物理学科知识、计算知识与教学法知识（Lane et al., 2023, PDF pp. 2-4; journal pp. 303-305）。

该研究还提示了一个更具体的缺口：许多专业学习活动提供课程或技术培训，但较少解释教师如何获得设计和实施整合活动的能力；已有工作所述的障碍包括课程空间不足、计算知识不足、缺少情境化实施想法和持续支持（PDF pp. 5-6; journal pp. 306-307）。这并不证明所有教师都具有同样需求。它构成本项目的待检验问题：不同经验、资源条件和课堂情境下，教师如何描述这一衔接过程，哪些支持被认为可用，哪些支持未能转化为课堂行动？

## 2. 研究问题

1. 高中物理教师如何界定计算思维和 Python 在其物理教学中的作用？
2. 教师从尝试计算活动到设计、实施和修订课堂活动时，分别遇到哪些知识、时间、资源和协作约束？
3. 哪些专业学习支架有助于教师把计算活动与既有物理课程目标相连接？

## 3. 概念框架与分析边界

本研究将 Lane 等提出的“计算知识 - 物理中的计算应用 - 物理-计算整合教学法知识”路径作为**敏感化概念**，用于形成访谈追问和第二轮比较，不把它预设为必然出现的主题。来源研究使用工作坊末期开放式问卷并先进行开放概念编码、再以 CTIntegration 的交集作轴心编码，且通过不直接参与工作坊的作者进行同行复核（PDF pp. 10-13; journal pp. 311-314）。

本项目保留与该设计不同的可能性：教师资料可支持、修正、细化或反驳该路径。任何主题只有在能回到去标识化资料的完整意义片段时才进入候选结果；来源文献只支持研究问题和理论框架，不支持本项目的经验主张。

## 4. 方法

### 4.1 研究设计与抽样

采用定性描述性研究和最大差异目的性抽样。招募矩阵至少记录任教年级、既有编程经验、可用设备/课程空间、是否实施过计算活动与学校支持条件。纳入对象为具有高中物理教学经验、愿意讨论计算整合实践并完成知情同意的教师。排除标准、预期信息丰富度、资料收集停止规则和研究者角色说明在开始招募前冻结。

不预设“多少人即饱和”。研究者将以新资料对代码与主题的贡献、反例是否持续出现及矩阵覆盖情况作为停止讨论依据，并在报告中说明实际停止理由。

### 4.2 资料链与访谈提纲

每位参与者可提供四类互补资料：

- 背景问卷：教学经历、既有计算经验、课程与资源条件。
- 一次半结构式访谈：60 分钟左右，录音转写后去标识化。
- 一次课后开放反思：针对一次计划或实施过的计算活动。
- 自愿提供的去标识化教学设计、任务单或代码片段，不收集学生身份资料。

核心访谈追问为：

1. 你如何理解计算思维在物理课堂中的作用？
2. 请描述一次选择、修改、实施或放弃 Python/计算活动的具体经历。
3. 你如何把物理概念、代码、学生任务和评价连接起来？
4. 语法错误、时间、设备、学生差异或课程进度如何影响你的决定？
5. 哪些示例、同伴协作、资源或技术支持真正有用，哪些不够用？
6. 如果再次实施，你会保留、删除或修改什么，为什么？

### 4.3 数据治理

原始资料只进入项目私有数据区，不进入文献检索库。上传后先记录版本与 SHA-256，并进行明显直接标识符的风险检查；研究者确认处理范围后才可冻结。系统不声称自动完成伦理审查、知情同意或完全去标识化。研究团队须在实际开始前完成相应审批、访问控制、保留期限与删除流程。

## 5. 分析计划

分析单位是保留上下文的意义片段，而不是孤立关键词。顺序如下：

1. 冻结研究问题、资料版本和抽样记录，写入研究者反思备忘。
2. 对访谈、反思和教学材料进行开放编码，保留代码定义、纳入规则、排除规则和原始片段。
3. 以计算实践、物理-计算应用、教学法与课堂支架作为第二轮比较维度，同时保留无法放入这些维度的新代码。
4. 跨参与者、经验背景和资料类型比较，主动检索反例与不一致解释。
5. 由未参与首轮编码的同行进行审计式复核，记录争议、修订与未解决问题。
6. 仅将带有资料片段、冻结版本和解释边界的主题写入结果；关键词辅助生成的候选不等同于完成编码。

该计划借鉴来源研究的两轮编码逻辑，但不复制其问卷题目、样本、主题数量或结论。来源研究中，参与者在“需要更多支持”与“计算整合的理想”之间出现差异，是一个值得本项目追问、而非预先确认的现象（PDF pp. 12-13; journal pp. 313-314）。

## 6. 可信度、局限与预期贡献

可信度依赖于多源资料比较、反思备忘、负例分析、代码本和决策审计、独立同行复核，以及对无法支持的解释保持可见。成员反馈是否采用、如何采用，需按伦理和研究问题另行预注册，不能作为自动通过的质量标签。

预期贡献是形成一份可追溯的专业学习需求图谱：区分编程熟练度、物理建模应用和课堂教学支架，并把抽象的“支持教师”转化为可测试的工作坊、资源和协作设计要求。局限是本项目仍将依赖自愿参与者、情境化资料与研究者解释；它不以小样本定性资料估计普遍比例或证明干预效果。
