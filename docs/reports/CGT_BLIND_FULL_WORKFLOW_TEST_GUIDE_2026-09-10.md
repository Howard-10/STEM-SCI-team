# STEM-SCI 计算扎根理论盲测全流程操作指南

## 1. 这次测试要验证什么

本次测试使用公开的德语学生物理问题解决文本，验证 STEM-SCI 能否在不知道原论文结论的情况下，完成以下完整链条：

1. 从一个模糊研究想法开始，像研究导师一样逐轮澄清。
2. 主动要求并审计真实数据，而不是让用户先写完整研究方案。
3. 形成可修改的研究问题和计算扎根理论方案。
4. 生成、审查并执行可复现的 Python 分析代码。
5. 先由计算方法发现模式，再由研究者解释和修订主题。
6. 用监督模型、稳健性分析和组间比较确认结果。
7. 先冻结结果，再写完整论文，避免写作反过来改变结果。
8. 最后在 STEM-SCI 之外把生成稿与原论文比较。

这不是“让系统照着原论文复述”。真正有价值的测试是：只提供研究背景和方法思想，不提供原论文的主题名称、数字和结论，观察系统能否独立得到相近但不抄袭的结果。

## 2. 文件隔离规则

| 文件 | 什么时候使用 | 能否上传到生成论文的 STEM-SCI 项目 |
| --- | --- | --- |
| `Textual_descriptions.csv` | 数据审计阶段 | 可以，作为主要文本数据 |
| `Additional_data.csv` | 数据审计后期、组间比较前 | 可以，作为样本边界和背景变量 |
| `paper_tschisgale_2023.pdf` | 最终外部对照 | 不可以，候选论文冻结前始终不上传 |
| `dat_human_recoding.csv` | 最终外部对照或标签一致性检查 | 不可以，独立主题和标签冻结前不上传 |
| `CGT_step_*.py` | 最终代码结构对照 | 不可以，先让系统自己生成代码 |

必须注意：只上传 `Textual_descriptions.csv` 时，系统只能完成文本主题分析。该文件没有奥赛分组字段，也不能独立解释为什么原论文使用 417 人。要完成奥赛参与者与非参与者比较，必须在后续单独上传 `Additional_data.csv`。

## 3. 测试前准备

1. 确认前端和后端已经启动。
2. 新建一个项目，不要复用旧项目。
3. 项目名建议填写：`学生物理问题解决文本的计算辅助定性研究`。
4. 研究方向只填写：`物理教育中的问题解决与文本分析`。
5. 进入项目后再点一次“新建对话”。
6. 此时不要上传任何文件，不要填写 DOI，不要提原论文作者、标题、五个主题或结果数字。
7. 每次只发送本指南的一轮。系统回答合格后再进入下一轮。

如果系统提问顺序稍有不同，只要问题含义相同，就使用对应答案，不必强行要求逐字一致。

## 4. 第一阶段：从模糊想法到研究问题

### 第 1 轮：只给模糊研究想法

你输入：

```text
我手上有一批学生描述自己如何解决一道物理题的文字。我感觉这些回答里可能存在几种稳定的思考方式，但我还不知道应该怎样把它变成一个可靠的研究。请你像研究导师一样一步一步引导我，每次只问一个最关键的问题，现在不要检索、不要分析、不要写完整方案。
```

系统应当做什么：

- 简短复述你的目标仍然模糊。
- 只问一个问题，优先问“你最想弄清什么”。
- 不显示两张研究路径卡，不启动分析任务，不生成论文。

合格问题示例：

```text
你最想弄清的是学生使用了哪些物理知识，还是他们组织整个解题过程的方式？
```

### 第 2 轮：回答研究目标

你输入：

```text
我更想知道学生是怎样组织解题思路的，包括他们先做了什么假设、调用了哪些物理概念、怎样进行定量推导，以及最后怎样表达答案。我暂时不关心得分高低。
```

系统应当做什么：

- 识别研究焦点是“问题解决过程的语义结构”，不是成绩预测。
- 下一次只问研究对象或具体情境。
- 不应提前断言有几类主题。

### 第 3 轮：回答研究对象和任务情境

系统大意应问：`这些文本来自什么学生、什么任务和什么语言？`

你输入：

```text
文本来自中学生或高中阶段学生，内容是他们用完整句子描述怎样解决一道竖直圆环运动问题。题目涉及无摩擦运动、能量关系和圆周运动。原始回答主要是德语，学生编号已经匿名化。
```

系统应当做什么：

- 记录对象、任务和语言。
- 识别德语文本、物理公式和匿名编号会影响分句与嵌入模型选择。
- 下一次只问预期贡献或论文最终要回答什么。

### 第 4 轮：回答预期贡献

你输入：

```text
我希望先从文本中归纳出几类可解释的问题解决主题，再检查这些主题是否稳定。最终想写成一篇公开二手资料再分析论文，重点说明计算方法和人工解释怎样配合，而不是声称发现了普遍规律。
```

系统应当做什么：

- 把项目定位为公开二手资料的计算辅助定性研究。
- 区分“主题候选”“经过人工复核的主题”和“经过模型确认的主题”。
- 下一次询问资料来源和可用字段。

### 第 5 轮：回答资料来源，但还不上传

你输入：

```text
资料来自一个公开研究项目。我目前有一份 CSV，应该包含匿名学生编号和每名学生的一段德语解题描述。可能还有一份背景变量表，但我想先让你告诉我需要哪些文件和字段，再决定什么时候上传。
```

系统应当做什么：

- 主动要求先上传主要文本 CSV。
- 说明最低需要 `Stu_ID` 和 `Text`。
- 如果要做组间比较，还需要能通过 `Stu_ID` 连接的分组表。
- 不应假装已经读到文件。

### 第 6 轮：确定分析单位

系统大意应问：`一名学生的整段回答作为一个单位，还是要拆成更小的文本片段？`

你输入：

```text
我认为一名学生的一段回答可能同时包含多个主题。模式发现可以先以句子为单位，但必须保留 Stu_ID，最后再回到学生层面汇总。公式可能被错误切开，所以请把公式保护和分句敏感性检查写进方案。
```

系统应当做什么：

- 确认“句子是编码单位，学生是聚合和推断单位”。
- 识别同一学生多个句子并非独立观测。
- 记录公式保护、短句阈值和分句方法需要做敏感性分析。

### 第 7 轮：确定方法边界

你输入：

```text
我想采用三阶段的人机协作流程：第一阶段让计算方法探索性发现模式；第二阶段由研究者阅读代表句、边界句和噪声句，修订并合并主题；第三阶段再用监督模型和交叉验证检查最终主题能否覆盖全语料。现在请先判断这个路线是否适合，不要预设主题数量和名称。
```

系统应当做什么：

- 将路线识别为计算扎根理论或相近的计算辅助定性路线。
- 解释机器负责规模化发现和确认，人负责语义解释与边界判断。
- 指出这不是纯自动主题模型，也不是纯人工编码。
- 给出一个待确认的设计摘要，但仍只问一个决定性问题。

### 第 8 轮：说明现实约束

你输入：

```text
代码使用 Python，必须保存随机种子、软件版本、输入文件哈希、中间数据和图表。先做小规模试运行，确认环境可用后再跑完整分析。任何正式结果都必须来自实际执行输出，不能从我的描述或已有论文中推断。
```

系统应当做什么：

- 形成研究设计候选和复现要求。
- 给出“是否进入数据导入和审计”的明确 Gate。
- 不应越过 Gate 直接生成结果。

如果它没有提出 Gate，你输入：

```text
请把目前内容整理为一个可修改的研究设计摘要，并明确列出下一步的数据导入 Gate。没有我的确认，不要执行分析。
```

## 5. 第二阶段：上传和审计主要文本 CSV

### 第 9 轮：确认进入数据导入

你输入：

```text
我确认当前研究目标和三阶段方法边界。现在进入数据导入，但只做文件识别和数据审计，不做主题分析。
```

随后点击对话框左下角 `+`，上传：

```text
Textual_descriptions.csv
```

### 第 10 轮：要求系统证明它真的读取了文件

你输入：

```text
请先报告你实际读取到的文件名、行数、字段、字段类型、缺失值、学生编号唯一性、完全重复记录和文本完全重复情况。所有数字必须从本轮上传文件计算，不要引用其他项目历史，也不要开始清洗。
```

合格审计结果应接近：

- 550 行、2 列。
- 字段为 `Stu_ID`、`Text`。
- `Stu_ID` 无缺失，550 个唯一值。
- `Text` 有 78 个缺失，因此非空文本为 472 条。
- 完全重复行 0 条。
- 非空文本约有 436 个不同取值，说明存在内容完全相同的文本，但不能在未检查前自动删除。
- 文本为德语，并包含换行、公式、缩写和拼写差异。

不合格表现：

- 把 550 直接说成“有效样本”。
- 声称已经得到 417 人。
- 没报告 78 个缺失文本。
- 报告了 CSV 中不存在的分组或性别字段。

答偏时输入：

```text
暂停。你刚才的回答没有证明读取了当前 CSV。请只根据当前附件重新计算审计表；逐项列出原始行数、非空文本数、唯一 Stu_ID、缺失值和重复文本，不要使用历史项目数字。
```

### 第 11 轮：决定如何处理 78 个缺失文本

系统应当询问你是否排除缺失文本，以及重复文本如何处理。

你输入：

```text
排除 Text 为空的 78 条记录，但保留原始文件不变，并生成排除清单。内容完全相同的文本先保留，因为它们来自不同 Stu_ID，可能是真实重复作答；请单独加 duplicate_text 标记，不要静默去重。当前得到的 472 条只能叫“具有非空文本的候选样本”。
```

系统应当输出：

- 原始数据、处理后数据和排除清单三者分离。
- 550 -> 472 的样本流转表。
- 不将 472 宣称为最终论文样本。
- 询问是否存在背景变量或进一步的纳入边界。

## 6. 第三阶段：补充背景表并冻结 417 人样本

### 第 12 轮：上传背景变量表

你输入：

```text
我还有一份通过 Stu_ID 连接的公开背景变量表。请告诉我上传后你会怎样检查连接关系、分组编码和缺失值，仍然不要开始主题分析。
```

系统应当说明：

- 检查主键唯一性和一对一连接。
- 报告只在文本表、只在背景表和成功连接的 Stu_ID。
- 解释分组字段含义前要求用户确认数据字典。
- 不能仅凭字段名猜测 0 和 1 的意义。

然后上传：

```text
Additional_data.csv
```

### 第 13 轮：审计背景表和连接结果

你输入：

```text
请审计背景表并与非空文本记录按 Stu_ID 做一对一连接。先报告连接结果、未连接编号和各字段缺失；不要把 Control_group 的 0/1 自动解释成实验处理。
```

合格结果应接近：

- 背景表 417 行、5 列。
- 字段为 `Stu_ID`、`Class`、`Gender`、`Still_phy`、`Control_group`。
- `Stu_ID` 无缺失且 417 个唯一值。
- 与非空文本内连接后得到 417 名学生。
- `Control_group` 有两个取值；必须等待编码解释。
- `Still_phy` 有大量缺失，不能直接用于主分析。
- `Class` 中存在一个非数字占位值 `---`。

### 第 14 轮：解释背景字段和比较边界

你输入：

```text
字段含义如下：Control_group=0 表示物理奥赛参与者，Control_group=1 表示非参与对照组；Gender=0 表示男性，Gender=1 表示女性。Class 是年级，Still_phy 是对照组是否仍在学习物理的相关信息。分组不是随机分配，而且两组的数据收集形式可能不同，所以只能做描述性或关联性比较，不能写因果结论。
```

系统应当做什么：

- 记录 145 名奥赛参与者和 272 名非参与者。
- 记录性别构成和年级缺失/异常，但不把这些数字写成因果解释。
- 提醒组间比较可能受到选择偏差、作答形式和文本长度影响。
- 提出冻结数据版本的 Gate。

### 第 15 轮：冻结分析数据

你输入：

```text
我确认主分析样本采用能够同时连接非空文本和背景变量的 417 名学生。请冻结这一版本，生成 SHA-256、纳入排除流程、字段字典和数据边界说明。原始 550 行文件必须保留，任何后续处理都从冻结版本派生。
```

合格输出必须包含：

- 原始 550 行、78 条空文本、472 条非空文本、417 条成功连接、55 条因无背景记录未进入主分析的流转说明。
- 输入文件哈希和冻结时间。
- 417 个 `Stu_ID` 的冻结清单或可审计索引。
- “公开二手资料再分析”“非随机组间比较”“不做因果推断”。
- 下一步进入分析代码生成，而不是直接写论文。

## 7. 第四阶段：让系统生成分析代码

### 第 16 轮：先生成代码规格，不直接生成整套代码

你输入：

```text
现在只生成分析代码规格，不写论文。请把程序拆成可独立审查的模块：数据审计与冻结、德语分句与清洗、句子嵌入、UMAP 与 HDBSCAN 多随机种子探索、聚类审阅包、人工修订标签导入、监督模型确认、组间比较、稳健性分析和结果汇总。每个模块列出输入、输出、随机性、失败条件和测试。
```

系统合格回应：

- 不把全部逻辑塞进一个脚本。
- 原始数据只读，输出到独立目录。
- 每个中间表都保留 `Stu_ID` 和稳定的 `Sentence_ID`。
- 明确代码生成、代码审查、执行审批三个不同 Gate。
- 不预设最终主题名称和组间结果。

在执行前审查这段代码。重点检查：是否误把 nan 当文本；是否用行号冒充 Stu_ID；是否会把公式拆成无意义碎片；是否修改原始文件；是否固定随机种子；是否把 417 名学生误写成 417 个句子。请先给审查结论和修改 diff，再请求执行批准。

系统应当先报告问题和修订，不应直接声称运行成功。

批准只执行数据审计和预处理。先运行完整 417 人数据，但不要下载大型模型、不要做嵌入和聚类。执行后报告实际句子数、每名学生句子数分布、被短句阈值排除的片段示例和公式切分错误示例。

我确认以句子为主要编码单位，20 字符作为基线阈值，但请保留 10 和 30 字符阈值的敏感性结果。任何包含明确物理关系的短公式片段不得仅因字符数不足而自动删除；请将这些片段放入人工复核清单。冻结预处理版本后再生成模式发现代码。

## 8. 第五阶段：无监督模式发现

### 第 21 轮：生成嵌入、降维和聚类代码

你输入：

```text
请生成模式发现代码。基线采用适合德语句子的预训练嵌入，将每个句子转成向量；再使用 UMAP 降到 5 维，参数 n_neighbors=15、metric=cosine、min_dist=0；随后使用 HDBSCAN，min_cluster_size=15、metric=euclidean、cluster_selection_method=eom。不要预设簇数。先设计 20 个随机种子的烟雾测试，再设计 100 个种子的试运行和 1000 个种子的正式稳定性运行。
```

说明：这些是从原研究方法思想中提取的基线参数，可以告诉系统；不能告诉系统原文最终出现多少簇或哪些簇被合并。

系统应生成：

- `02_embed_and_cluster.py`。
- 模型名称、模型版本和缓存位置记录。
- 每个随机种子的簇数、噪声比例、聚类持久度和标签输出。
- 失败时可恢复的检查点，避免每次重算嵌入。
- 2 维可视化只用于展示，5 维表示用于聚类。

### 第 22 轮：批准 20 种子烟雾测试

你输入：

```text
先批准 20 个随机种子的烟雾测试。执行后只报告环境、运行时间、内存、各次簇数、噪声比例和是否出现崩溃；不要根据 20 次试运行宣布最终主题。
```

通过标准：

- 嵌入只计算一次并复用。
